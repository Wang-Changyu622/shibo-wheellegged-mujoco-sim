# 上台阶改进与学习控制实施计划

日期：2026-11-20。这是未来候选方案，不是已经训练成功的结果。用户最新决定：**学习先搁置，本轮不搭建训练环境、不启动训练。** 当前冻结基线是提交 `1cecec9f83af218b2b19618ab71cff5d529c2f99`；保留其全部硬件限制、140项测试、默认五任务和独立腿控制证据。额外加速度计优化仍留在后续独立阶段。

## 先解决什么

用户明确的能力目标是**更高台阶和连续台阶**；平顺性、停稳和执行器限制作为必须同时检查的约束。当前6mm台阶的通过标准包含真正双轮上台、末窗停稳和禁止机身/腿辅助支撑，但没有要求边缘速度连续或限制冲击；因此通过不等于运动质量理想。专项结果见 [台阶诊断](step_diagnostics.md)，具体代码问题见 [审查](code_review_next_stage.md)，相关项目与固定源码证据见 [开源学习方案比较](learning_references.md)。

本轮12组确定性设置中，5组通过安全越阶及停稳。当前6mm、髋目标−0.30rad、速度命令0.18m/s的边缘速度从接触前均值0.22551m/s降到0.05859m/s，下降74.02%；0.10/0.14m/s在两种腿高下都卡边。将该高腿配置速度命令增加至0.22m/s，受载接触滑移RMS升到约0.331m/s。所测8/10mm配置未通过。这说明简单减速、增速或单独伸腿都存在代价；这12组不是随机成功率估计，也不能据此认定6mm是硬件最大能力。

建议先实现**学习式速度和腿姿态调度，保留LQR低层平衡**。模型、执行器、地形评分和状态接口稳定后，再把端到端PPO作为公平对照。学习可以改进动作时序和接触策略；能否越过更高台阶仍受轮径、闭链行程、轮驱动力、舵机动态和摩擦限制，必须通过实测边界判断。

| P1 | 高台阶和连续台阶的参数化能力基准 | 地形高度、位置、宽度、踏面深度、级数、倒角、摩擦是每个episode的显式配置；评估从同一几何配置/编译模型取值；逐级记录进入/持续支撑/离开，保存卡边、跌倒、辅助支撑等失败原因 |
| P2 | 建立CPU学习环境和简单非学习调度基线 | Gymnasium风格reset/step、seed、terminated/truncated、观测/动作归一化、奖励分项、固定控制时钟；随机动作/固定动作/当前LQR回归可复现；不用ROS消息往返做训练内环 |

P0中的修正是本次审查后的待实施事项。本轮没有改写已通过的控制核心，也没有启动训练。简单非学习调度必须经过合理调参，避免拿明显不合适的固定速度作为唯一对照。

## 高台阶与连续台阶的能力边界（待实施）

先测单级高度，再改变踏面深度和级数，避免把多个难度变量同时增加而无法解释失败。报告台阶高度/轮径（本车轮径37mm）、踏面深度/轮径、级数、总升高和平台长度；保留实际毫米数。该车只有一对同轴轮，不能套用四足或多轴轮车的前后轴跨越逻辑。

单级先保留本次4/6/8/10mm锚点，在相同执行器限制下比较接近速度、伸腿时机、俯仰参考和接触后恢复策略；记录真实上下行程、离地/落地、卡边位置和饱和。必要时另设明确的跳跃越阶任务，保留腾空和落地判据，不能把冲过去与持续轮接触爬阶混作同一种能力。

连续台阶从已验证可行的单级高度开始，先两级再多级，同时扫描踏面深度。每一级都按实际几何检查预定路径、轮轴越界、支撑/飞行状态、姿态和恢复；最终在顶层平台停稳。测试需区分“逐级通过”和“有意跨级跳跃”，不能绕开侧面或一次跳过多级后自动得到逐级成功。未知下一台阶的预判需要前视信息或已知地形假设；现有IMU与编码器历史不能提前提供尚未接触的台阶位置。

本轮只明确该测试设计，尚未新增连续台阶场景或宣称更高台阶已通过。

## 第一版策略接口

先把单级直台阶任务限定为前后方向，偏航目标保持零。每次策略输出三个连续量：`[v_cmd, q_left, q_right]`。输出经单独的动作映射器转成m/s和rad，再使用现有平衡控制器与执行器约束。可从`v_cmd∈[-0.05,0.25]m/s`、`q_left/right∈[-0.30,0]rad`的开发范围开始，依据边界试验冻结；这些是建议值，不是已验证可覆盖的任务范围。

- 先学习接近速度、两腿高度和过边缘后的恢复时序；高度保持原每腿名义参考斜坡，不为训练放大舵机能力。
- 第一版不输出世界位姿、起跳冲量、外力或被动关节位置。轮电压仍由LQR产生；策略不能直接改写`qpos/qvel`。
- 后续若三维调度确实受限，再比较有界轮电压残差或四执行器端到端策略，分别保存动作语义和限制，不能把位置目标当作髋力矩。
- 跳跃作为后续独立任务/可选高层技能，不先把过阶、跳跃、转向、单边桥全部塞进同一个训练目标。

建议起始策略频率50Hz，原控制2kHz、物理0.5ms：策略每40个物理步更新一次，其间低层控制仍逐步反馈。只有把物理与控制时钟分开后，才可以在保持控制周期不变的情况下把物理步长减半进行数值对照。50Hz是待测起点；要同时记录策略推理耗时、延迟、动作变化率和仿真实时率。

## 观测与信息公平性

采用两套明确标注的信息条件：

1. **地形已知上限实验**：允许台阶相对距离/高度和仿真真值，验证受限机构在理想信息下能否改善上阶。这一结果不得称为无感知自主越障。
2. **可部署信息实验**：使用已有IMU得到的角速度/姿态估计、髋编码器位置/速度、轮编码器速度、命令和动作历史。速度与接触需从实际可用信号估计；仿真真值仅用于critic、奖励和评估，明确标出用途。

仅限制actor输入还不够：目前LQR内部也直接读取MuJoCo全局位置和真实轮轴速度。必须让整个低层控制器通过可替换的状态接口运行，才能声称部署路径使用可测信号。LQR的相对位置误差、偏航参考误差、速度/髋参考、积分项和跳跃阶段等内部记忆可以作为可访问控制状态，避免策略面对隐含状态而无法解释动作。

没有前视传感器时，接触前未知台阶可能不可观测。历史堆叠或循环网络可帮助估计已发生的打滑/接触变化，但不能凭空提供尚未观测到的台阶位置。若目标要求提前减速、提前抬腿，应单独评估前视感知方案或明确使用已知地形；不能把仿真高度图悄悄给actor。此阶段不加入额外加速度计。

## 奖励与终止条件

奖励按物理时间积分，跨策略频率保持相同量纲；记录每个分项及其对总奖励的贡献。建议从少量可解释项开始：

- 真正向目标区域推进及双轮持续上台的奖励；用机身/轮轴实际位移，避免轮子空转刷分。
- 俯仰/横滚偏离、角速度、动作变化和执行器饱和惩罚。
- 轮地接触点相对切向速度、冲击与停稳时间的质量代价。接触峰值需同时报告采样周期和步长敏感性，不能只优化一帧力峰。
- 明确跌倒、超出机构边界、异常求解器复位、非轮持续支撑、超时未通过等终止原因；将时间上限截断与物理失败区分，正确处理PPO的bootstrap。

防止策略选择永久停车、反复倒退、绕开台阶、压腿撑地或用高频动作利用接触求解器。平台成功必须具有正确路径和持续支撑，训练奖励不能代替独立验收器。能量项目前只能称为机械功/输入代理；电压模型未包含实测电流，不能宣称精确电耗。

## 课程、随机化和对照

先做0/2/4/6mm单级台阶，再依据可行域加入8/10mm或其他高度；进入更难高度需要固定验证集上的稳定通过和运动质量约束达标。之后在可行高度下扩展双级、多级及踏面深度课程。随机化台阶位置与起始距离，防止策略记住当前固定1–4秒指令和固定0.20m边缘。随后逐项增加摩擦、初始俯仰/速度、横向偏差、执行器增益/时延和负载误差；参数区间由标定或有记录的敏感性结果确定。

| 对照 | 目的 |
|---|---|
| 当前增益调度LQR + 固定预伸腿/固定速度 | 保留原始可复现锚点 |
| 相同低层控制 + 简单事件式速度/腿调度 | 检验收益是否只来自更好的动作时序 |
| LQR + 学习式三维调度 | 检验学习在相同执行器和信息条件下的额外收益 |
| 端到端或电压残差策略（后续） | 判断进一步自由度是否值得增加训练和迁移成本 |
| 去掉历史/随机化/预览信息的消融 | 分离状态估计、训练覆盖和地形先验的贡献 |

训练、调参和最终测试种子/地形集合分别固定。所有方法使用相同初态、扰动、动作限制、评估时长和可用信息；失败试次保留在成功率统计中。报告高度/轮径比、通过率、条件通过时间、速度损失、姿态、接触冲量、滑移、饱和、非轮支撑和停止后的恢复。

## 工程拆分与本机资源

建议保持小模块：`terrain.py`保存地形配置/构建/几何查询；`observations.py`区分真值、可测与估计；`actuation.py`定义动作映射及动态限制；`envs/step_env.py`负责回合生命周期；`rewards.py`提供可审计的奖励分项；`training/`只负责算法、配置和checkpoint；`evaluate.py`保留独立物理评估职责。CLI、键盘和ROS均复用核心，学习依赖作为可选安装组，不让普通查看模型必须安装训练栈。

本机实测为RTX4050 Laptop、约6GB显存、15GiB系统内存；当前`.venv`未安装torch、JAX、MJX、MuJoCo Warp或Gymnasium。先保留现有CPU环境，新建独立训练环境并锁定兼容版本。最新版上游依赖可能与本项目MuJoCo3.17不兼容，具体固定版本见开源比较，不能直接升级现有环境后沿用旧证据。

GPU试验不为吞吐删除四杆约束或碰撞。可在训练模型中省去156个可视网格的渲染负担，但质量、惯量、关节、闭链和接触几何必须保持并做一致性验证。先测编译时长、16/64/128环境的步速和峰值显存，再决定是否采用本机训练、分阶段CPU试验或外部算力。

## 暂存的后续路线

用户已决定暂不开展学习。若未来恢复，应先完成P0、P1、P2，进行小规模CPU接口验证；扩大训练前先通过P3的后端与资源检查。研究问题建议收敛为：**在真实执行器限制和有限观测下，学习式接触/姿态调度能否扩大微型轮足车通过更高与连续台阶的可行域？** 是否具有论文贡献，取决于之后的公平对照、可重复实验、模型标定与实机证据。
