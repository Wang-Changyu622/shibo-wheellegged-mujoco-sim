# 执行器参数、2S 供电与可信度

当前硬件配置为用户确认的 **2S、标称 7.4 V 电池**。默认仿真采用 `hardware_2s`：轮电机按原固件的 SinePWM 线性调制范围限制实际 q 轴相电压至 ±3.7 V，髋舵机采用 6 V 规格中的额定转矩 **0.14709975 N·m**。这是一组受已知规格约束的工程近似，尚不是实机标定模型。

机器可读参数保存在 [hardware_parameters.json](../config/hardware_parameters.json)。原 `reference` 参数显式保留，用于复现历史结果；旧任务成功、步长收敛和跳跃数据不能自动继承为新硬件配置的验证结论。论文中应记录 profile、参数清单的哈希、模型质量/惯量版本、控制参数及软件提交版本。

## 两个 profile

| 参数 | `reference` | 默认 `hardware_2s` | 证据或性质 |
|---|---:|---:|---|
| 标称直流母线 V | 未建模 | 7.4 | 用户确认 2S；没有测量瞬时电压/压降 |
| 轮输入电压限制 V | ±7.4 | ±3.7 | 新 profile 表示实际 q 轴相电压；原值只是旧仿真输入范围 |
| 电压转矩系数 a，N·m/V | 0.01 | 0.01 | 保留的待辨识工程假设 |
| 电气速度系数 b，N·m·s/rad | 0.0001 | 0.0004774648293 | 新值由声明的 Kv 电压约定推导 |
| 单轮执行器转矩上限 N·m | 0.08 | 0.0588 | 新值只是卖家 3S 转矩的外层代理上限 |
| 单髋连续仿真转矩上限 N·m | 0.15 | 0.14709975 | STS3032 在 6 V 的额定 1.5 kgf·cm |

两个 profile 都保留模型中每个轮关节 `0.00005 N·m·s/rad` 的机械粘性阻尼；它与电机反电动势导致的速度项分别计算。髋位置伺服的刚度、阻尼和带宽仍是仿真假设，厂家额定转矩并不能证明这些内部控制参数正确。`reference` 的旧转矩/电压范围不代表用户确认过的硬件能力。

## 原固件与电压控制语义

核查用户本地 `wl_pro_robot.ino`：两个 `BLDCMotor(7)` 指定 7 对极，两个驱动器声明 `voltage_power_supply = 8`，控制模式为 `TorqueControlType::voltage`，没有设置绕组电阻、Kv 或电流反馈控制。附带的 `Simple_FOC.zip` 版本是 **2.2.1**，默认调制为 SinePWM；这里以本地代码为实际行为依据，不把新版 API 的不同模式名称套到旧固件上。源码及 ZIP 哈希在 JSON 中可追溯。[官方旧版电压模式说明](https://olddocs.simplefoc.com/v2.3.2/voltage_torque_mode)

SinePWM 中三相命令围绕半母线电压平移，线性范围为 `|Uq| ≤ Vbus/2`。超出后相电压被裁剪，进入过调制，不能继续用线性 `τ=aUq−bω` 假装输出等比例增长。SVPWM 的线性上限不同，但本地固件没有选择它。[SimpleFOC 调制说明](https://docs.simplefoc.com/pwm_modulation)

这里存在两个必须区分的电压：

1. **实际母线电压**：用户确认标称 7.4 V，负载下测值待补。
2. **软件声明电压**：原程序为 8 V，用于把相电压命令换算成 PWM 占空比。

在未裁剪区域，若实际母线恰为 7.4 V 而声明仍为 8 V，则实际相电压约为原始软件 Uq 的 `7.4/8 = 0.925` 倍；原始 Uq 的 ±4 V 线性边界对应实际 ±3.7 V。默认仿真的输入统一定义为**实际 q 轴相电压**。未来硬件适配必须校正驱动器声明电压或明确实现该换算，不应把仿真输入直接误认为原固件数值。当前没有修改或烧写用户硬件代码。

纯电压模式不等价于真实转矩/电流闭环：`τ=aUq−bω` 是准静态代理，没有绕组电感动态、实时电流限制、驱动压降、再生制动母线变化或热保护。仅限制仿真转矩不能证明电机电流不超过 3 A。

## Kv 与反电动势：为什么修正，以及修正到哪里

旧模型为 `τ = a Uq − b ω`，其中 `a=0.01 N·m/V`、`b=0.0001 N·m·s/rad`。若写为 `τ=a(Uq−Keω)`，隐含 `Ke=b/a=0.01 V·s/rad`，在同一电压约定下相当于 `Kv=60/(2πKe)=954.93 rpm/V`，约为图片 100 rpm/V 的 **9.55 倍**。这解释了原模型速度阻力偏弱的问题，但不能单凭这个比值断定真实 dq 常数。

默认 `hardware_2s` 采用名称为 `vendor_bus_equivalent_sine_2s` 的配对解释：图片 100 rpm/V 视为卖家使用母线电压描述的等效空载 Kv，SinePWM 下把电压与反电动势常数一起换成相电压约定：

```text
Ke_bus = 60 / (2π × 100) = 0.0954929658551 V·s/rad
Uq_max = 7.4 / 2 = 3.7 V
Ke_q   = Ke_bus / 2 = 0.0477464829276 V·s/rad
a      = 0.01 N·m/V                         # 待测，保持原工程假设
b      = a × Ke_q = 0.000477464829276 N·m·s/rad
```

这是一个有明确条件的转换近似。不能同时把 Uq 降为母线的一半，却又把已按母线定义的 Ke 原样当作相电压 Ke，导致重复降额；也不能反过来认为所有厂家 Kv 都必然按本约定测量。相/线、峰值/RMS、三相电机电流以及 dq 定义会带来不同系数。SimpleFOC 理论说明自身也给出 BLDC Kv 换算中的 √3 因子，进一步说明需要测量约定。[SimpleFOC 电压转矩理论](https://docs.simplefoc.com/voltage_torque_control)

该默认近似的电气无损空载上界是 `3.7/Ke_q = 77.4926 rad/s = 740 rpm`。加入现有机械轮关节阻尼 `d=0.00005` 后，理想自由轮稳态约为：

```text
ω = a × Uq_max / (a × Ke_q + d)
  = 70.146857 rad/s = 669.853143 rpm
```

这仍不含接触负载、库仑摩擦等损耗，不能说模型精确复现了厂家空载速度或实际地面车速。740 rpm 只是忽略机械损耗的电气上界；669.85 rpm 是当前代理模型自由轮的计算值。机械阻尼不得再次并入 b 后重复加到关节。

在零速、标称 2S 和该 a 值下，电压限制给出的最大转矩只有 `0.01 × 3.7 = 0.037 N·m`。因此 `.0588 N·m` 外层限矩并不意味着仿真承诺 2S 能提供卖家 3S 转矩。非零速度时转矩又受反电动势与限幅影响，模型尚未建立真实可持续的驱动/制动包络。

保留 `a=0.01` 的理由是现有证据不足以得到可靠替代值，而不是它已经正确。若机械转矩与电流是功率共轭、单位约定一致，才可将 Ke/Kt 与电阻联系起来；三相电机不能忽略峰值/RMS、相/线和母线电流差别。把卖家 `.0588 N·m` 除以“最大 3 A”得到 `.0196 N·m/A`，再与 `1/Kv` 强行联立推算绕组电阻，会把两个未证实同时成立的营销参数当成一个精确堵转点。本项目不做这种反推。

## 不确定性研究与后续辨识

JSON 给出的敏感性数值是实验设计候选，**不是测量置信区间**。建议固定默认控制器先检查执行器假设变化，再分别研究按各参数重新设计控制器后的性能，避免只报告每个模型各自最优结果。

- 在固定 Ke 下，对 `a` 使用 0.5、1、2 倍探索，并同步令 `b=aKe`，保证改变转矩增益时没有无意改变电气 Kv。
- 分别比较 `Ke_bus/2`、`Ke_bus/√3` 与“卖家 Kv 原本就表示实际 Uq”的 `Ke_bus` 三种**不同测量约定假设**。最后一种不能称为在默认母线约定上再做一次物理降额。所有运行继续遵守实际母线下的 SinePWM 电压边界。
- 舵机默认保持额定 `.14709975 N·m`。堵转 `.44129925 N·m` 只能在另行命名的短时峰值敏感性试验中出现，不能为了起跳成功默默替换默认值。
- 电压压降、实际舵机支路、轮电机发热与驱动限流尚未测量，不能由现有配置生成可信的实际连续工作包络。

下一步辨识应记录测量温度、母线电压与信号约定：测绕组相/线电阻和反电动势随机械转速的斜率，再测实际 Uq、静态转矩与电流的对应关系；记录舵机输出角速度、载荷、延时、死区与额定工况温升。官方提供电阻、Kv 和电感参数测试思路，可在有适当限流与测量条件时按实际驱动版本执行。[SimpleFOC 参数测试说明](https://docs.simplefoc.com/motor_params_test)

组件质量更新也需要证据分级：41 g 电机包含转子和定子，20.6 g 舵机包括壳体、齿轮与内部电机。厂家总质量可以约束 CAD 的质量分配，但不能唯一确定转动惯量、质心、实装附件和电池质量。名义质量更新必须与整机实测称量/质心测量区分。

## 配置读取约定

运行代码只从 `profiles[profile_name]` 读取约定的扁平数值字段，通过 `src/wheellegged/hardware.py` 的 `ActuatorProfile` 提供给模型。`catalog`、`sources`、`parameter_status` 和 `sensitivity_proposals_not_measured_bounds` 是溯源与研究元数据，不应自动作为新的执行器设置。

`schema_version=1`、`default_profile="hardware_2s"`；历史复现必须显式选择 `reference`。启动时应验证 profile 名称、数值有限且为正，并把实际选用的 profile 和参数写入结果。`bus_voltage_v=null` 只允许出现在不建模母线的历史 profile 中。后续若改变电压或 a/Ke，应重新计算电气 b、线性化和 LQR，而不是只修改某一处显示值。
